# 10 · 怎么把链路搭起来（两条路线：链式代理 / VPS + ISP）

> **这篇只讲"结构"和"路线选择"，不推荐任何具体软件。**
> 实现用的软件在 GitHub 上有很多成熟项目（本文末给了搜索关键词），**本仓库不复述它们的安装文档**。

---

## 一、先分清三个角色

| 角色 | 作用 | **必须固定吗** |
|---|---|---|
| **前置 / 中转** | 帮你"连出去"（突破网络限制） | ❌ **可以随时换** |
| **落地 / 出口** | **目标网站看到的那个 IP** | ✅ **必须固定** |
| **本地客户端** | 在你电脑上提供一个本地代理端口 | — |

**核心认知**：
> **目标网站只看"落地 IP"。前置换了，不影响你的身份。**
> 所以钱应该花在"落地"上，前置用便宜的就行。

---

## 二、路线 A：链式代理（前置 + 落地）

**结构**：

```
你的软件 → 本地客户端(127.0.0.1:端口) → 前置(机场/中转) → 落地(ISP 代理) → 目标网站
```

| | |
|---|---|
| **适合谁** | **已经有机场订阅的人**（大多数人的起点） |
| **成本** | 机场订阅费 + 落地费用 |
| **门槛** | 低 |

**要点**：
- 客户端里把"**落地**"配置成一个**上游代理（upstream / detour / dialer-proxy）**
- **前置节点负责"能连出去"，落地负责"身份"** —— 两个都要配
- 本地客户端最终会给你一个 `127.0.0.1:某端口`，把这个端口填给浏览器/软件即可

**坑**：

| 坑 | 说明 |
|---|---|
| **只填落地的 IP:端口 给软件** | ⚠️ **国内直连境外 IP 通常不通或极慢** —— 必须经本地客户端 + 前置 |
| 以为"前置换了，身份就变了" | ❌ **不影响**（网站只看落地） |
| 落地只给 SOCKS5 | ✅ **没问题** —— 本地客户端对外可提供 HTTP，软件照样能用 |
| 前置和落地用的是同一条线路 | ⚠️ 那"前置"就没意义了；前置的作用是**与落地不同路径** |

---

## 三、路线 B：VPS + ISP（自建中转）

**结构**：

```
你的软件 → 本地客户端 → 你的 VPS（自建中转） → 落地(ISP 代理) → 目标网站
```

| | |
|---|---|
| **适合谁** | 不想依赖机场、想要**完全自主**的人 |
| **成本** | VPS 月租 + 落地费用 |
| **门槛** | 中（要会买 VPS / 基本 Linux 操作） |

**⚠️ 最重要的一条**：

> **VPS 只做"中转"，不要当"落地"。**

**为什么"VPS 当落地"不行**：

| 问题 | 说明 |
|---|---|
| **它是机房 IP** | 风控库直接判 `Server = Yes` / datacenter |
| **段归属一眼假** | RDAP 注册持有者是**主机商 / 云商** —— 不是运营商 |
| **IP 段被滥用** | 云厂商的段几乎必然在代理黑名单里 |

**它的真实价值 = 替代机场当前置**：
- 优点：**路径自己可控、不经第三方机场**
- 代价：**要买、要维护、多数要实名/绑卡**

---

## 四、两条路线怎么选

| 维度 | **路线 A（链式代理）** | **路线 B（VPS + ISP）** |
|---|---|---|
| 成本 | 机场订阅费 | VPS 月租 + 落地 |
| 门槛 | **低**（有客户端就能配） | 中（要会买 VPS / Linux） |
| 稳定性 | 依赖机场 | **自己可控** |
| 隐私 | 机场能看到你的入口流量 | 只有你自己 |
| 实名 / 绑卡 | 机场通常不要求 | **多数 VPS 要** |
| 适合 | **大多数人** | 想完全自主、且愿意折腾的人 |

**两条路最终的"落地"是一样的** —— 都指向一个固定的 ISP 出口。

**⚠️ 一个高频误区**：

> **"自建 VPS 就能解决 IP 身份问题"** —— ❌ **不能。**
> **VPS 改变的只是"中转路段"，出口 IP 的身份仍然取决于你的"落地"。**
> 如果你的 VPS 直接出网，那你得到的就是一个**机房 IP**（见路线 B 的警告）。

---

## 五、不管走哪条，这几件事都要做

```
✅ 落地固定（前置随意）
✅ 一个账号 = 一个落地 IP（绝不多个账号共用一个 IP）
✅ 独立浏览器 profile（隔离 cookie / 时区 / 语言）
✅ 落地到期前续费（否则 IP 被回收，身份历史就断了）
✅ 定期验货（RDAP + Scamalytics，见文档 01）
```

**自查信号**（出现任一条就要重新检查环境）：
- 验证码变多
- 平台要求额外的身份验证
- Scamalytics 上该 IP 的 `Public Proxy` / `Residential Proxy` 变成 `Yes`

## 六、关于"用哪个软件"

**本仓库不推荐具体项目**，原因很实在：

| 原因 | 说明 |
|---|---|
| **更新太快** | 这类软件迭代极快，**今天的推荐明天可能就过时** |
| **同类项目多** | GitHub 上有一大批，**你自己按活跃度挑更靠谱** |
| **安装文档人家写得更细** | 本仓库复述反而容易过期、出错 |

**建议的挑选标准**：

| 标准 | 怎么看 |
|---|---|
| **是否支持"链式 / 上游代理"** | 路线 A 的硬需求（关键词见下） |
| 活跃度 | star 数 + 最近提交时间 |
| 是否跨平台 | Windows / macOS / Linux |
| 社区 | 出问题能不能搜到答案 |
| **别只看"能不能用"** | 还要看它是否**支持指定上游** |

**搜索关键词**（GitHub 上自己搜）：

```
# 客户端（路线 A 用）
clash / mihomo / sing-box / v2rayN / xray

# 链式代理的功能名（各软件叫法不同）
dialer-proxy / detour / proxy chain / upstream proxy / 前置代理

# 自建 VPS（路线 B 用）
xray install script / vps 一键脚本 / reality / hysteria
```

**⚠️ 一句提醒**：
> **搜关键词时优先看“它支持不支持指定上游代理”** ——
> 不支持的话，你没法做路线 A 的链式结构。

---

## 一句话总结

> **前置可以便宜、可以随便换；落地必须固定、必须自己验。**
> **VPS 解决的是"路径自主"，不解决"出口身份"。**
