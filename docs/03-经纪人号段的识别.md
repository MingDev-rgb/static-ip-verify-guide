# 03 · 经纪人号段的识别（为什么换了几家商家，买到的还是同一批货）

**这一篇解释一个现象：为什么你换了三、四家"下游"，拿到的还是同一批货？**

> 本文使用**真实名称与原始数据**（RDAP 注册记录、BGP 广播、风控库字段均为**公开可查**），
> 并给出**可复现的查询命令** —— **你可以自己验证每一条**。

---

## 一、什么是"IP 经纪人"

在 IP 供应链里，存在一类实体：

| 特征 | 说明 |
|---|---|
| 手里持有**大量 `LEGACY` 类型的老号段** | 通常是 1990s 分配的、注册信息简单的段 |
| **自己不面向终端用户** | 不做消费业务，只做批发 |
| **通过 Tier-1 骨干对外广播** | 所以你查到的"广播方"常是 NTT / GTT / Cogent 这类大厂 |
| **把号段批发给各级代理商** | 下游买的"原生住宅 IP"就来自这里 |

**关键**：他们**不是**住宅运营商，而是**号段的持有者与批发商**（有的还兼做 VPS/服务器业务）。

---

## 二、识别三招（完整方法见文档 01）

```
第 1 招：RDAP 查 netname  → 看注册持有者是谁（主机商？网络技术公司？）
第 2 招：RIPEstat 查广播  → 看现在挂在谁的 ASN 下播（Tier-1？）
第 3 招：Scamalytics      → 看 Organization Name + Server 字段
```

**第三招有个独门技巧**：
> Scamalytics 页面上会**同时显示** `ISP Name`（广播方）和 `Organization Name`（实际运营者）。
> **当两者不一致时**，`Organization Name` 往往就是**真正的持有者**。

---

## 三、实测案例：三个"下游"的德国货同源

> 数据采集时间：2026 年 9 月。**号段、ASN、字段值均为公开数据**（RIR 注册记录 / BGP / 第三方风控库）。

### 观察到的现象

| 来源 | 商家宣称 | 拿到的号段 | RDAP netname | 广播 ASN |
|---|---|---|---|---|
| **NovProxy**（购买） | 德国原生住宅 | `82.198.243.0/24` | **Arisk-Communications-inc** | `AS395793`（Arisk 自己的 ASN） |
| **LokiProxy**（展示示例） | 德国原生 ISP | `145.79.75.0/24` | — | **AS2914（NTT America）** |
| **LinkStatic**（客服测试） | 德国原生 ISP | `145.79.126.0/24` | **Arisk-Communications-inc** | **AS2914（NTT America）** |
| **YumiProxy**（展示示例） | 德国原生 ISP | `145.79.75.0/24`（**与 LokiProxy 的示例完全相同**） | — | **AS2914（NTT America）** |

### 三个数据的含义

1. **RDAP 的 `netname`**：`145.79.126.0/24` 的注册名**直接就是 `Arisk-Communications-inc`**（`country` 字段却是 **GB**，与"德国"不符）；
2. **RIPEstat 的广播 ASN**：这个段**挂在 NTT（AS2914）下面播** —— 所以商家可以宣称"**双 NTT 线路**"（听起来很高级，但 NTT 是 **Tier-1 骨干 = 最像机房的一类**）；
3. **Scamalytics**：
   - `ISP Name` = **NTT America**（迷惑项）
   - `Organization Name` = **Arisk Communications inc**（真相）
   - `Server` = **Yes**（商用服务器）
   - 页面文案：**"not a standard domestic connection, it is a commercial server"**

### 结论

> **NovProxy / LokiProxy / LinkStatic / YumiProxy 四家的"德国原生 ISP"，来自同一个号段持有者 `Arisk Communications Inc.`，只是通过不同的广播方式呈现。**
> （其中 **LokiProxy 与 YumiProxy 展示的示例 IP 完全相同** —— 这是"同一批货"最直接的证据。）
> **"换一家试试"在这个市场里无效 —— 你换的是零售门面，货架上是同一批货。**

## 四、为什么会这样（商业结构）

```
号段持有者（Arisk Communications Inc.）
      │  批发
      ├──────────► 代理商 A ──► 中文零售站（如 NovProxy） ──► 你
      ├──────────► 代理商 B ──► 中文零售站（如 LokiProxy） ──► 你
      └──────────► 代理商 C ──► 中文零售站（如 LinkStatic） ──► 你
```

- 终端零售商**没有能力自己找运营商签约**（起订量、资质、付款方式都是门槛）
- 所以他们**从同一批经纪人手里拿货**，然后**各自贴不同的标签**（原生 / 双ISP / 独享 / 双NTT）
- **同一个号段，在三家能卖出三种描述**

---

## 五、"双ISP""双NTT"这类词怎么来的

实测中发现了一个**技术上的解释**：

> 某些号段的 **ASN 历史**里，会记录**多个运营商**的痕迹 —— 例如：
> `145.79.0.0/16` 曾登记在 **Vodafone Libertel B.V.（AS33915，荷兰）** 名下，如今由 **NTT America（AS2914）** 广播。
>
> 于是这个段在数据库里**留下了两条 ISP 记录** → 商家就可以称它为"**双 ISP**"。

**所以"双ISP"更准确的翻译是**：
> **"这个段在历史上被转手过、挂过不止一家运营商的名字"** —— 它是**倒手的痕迹**，**不是"双线家宽保障"**。

---

## 六、给你的启示

| 现象 | 解读 |
|---|---|
| 商家敢展示"示例 IP" | ✅ 好事 —— 你可以立刻按文档 01 验证 |
| 商家只给"客服口头测试" | ⚠️ 测试 IP 往往**不代表正式库存**（可能只是空闲池） |
| 三家不同商家，价格/话术都不同 | ⚠️ 可能是**同一批货**（查 ASN 即知） |
| "双NTT / 双ISP / 多ISP" | ⚠️ 大概率是**倒手痕迹**，不是质量保障 |

---

## 一句话

> **不要问"哪家好"，要问"这个 IP 是谁的"。**
> **号段能被换标签，但换不掉注册记录。**

---

## 七、一个被忽略的细节：**"能选 ISP"的选项，只在美区档出现**

实测中发现的规律：

| 地区 | 面板上有"选择 ISP"的下拉吗 | 客服口径 |
|---|---|---|
| **德国档** | ❌ 没有 | 「**只有这个号段**」 |
| **美国档** | ✅ 有 | 可以要求换段 |

**这说明什么**：
> 它的**德国货架上只有一个号段**（经纪人的那批），所以**连"选 ISP"的界面都没必要做**；
> 而美国池里混着不同来源（既有 Tier-1 骨干，也有 ARIN 直接分配的小 ISP），所以**才需要让你挑**。

**给采购的直接结论**：
> 如果你要在下游买，**优先问美国档** —— 那是唯一"池子里有干净段"的地方。

---

## 八、补测：同一个经纪人会**跨国家**出现

**德国池同源**前面已经证明过了。后期补测又发现：**同一个经纪人的货，也会出现在"美国池"里**。

| 商家 | 国家档 | 实测 IP | RDAP 显示 | Scamalytics `ISP Name` | 真相 |
|---|---|---|---|---|---|
| 某下游 | **美国** | `64.50.130.19` | **GTT-CUSTOMER**（`ASSIGNMENT`） | **Arisk Communications inc** | ⚠️ **还是 Arisk** |

**它还带了一个伪装细节**：

```
hostname         = 64-50-130-19.client.dsl.net          ← 挂着 "dsl" 域名
Connection type  = dsl                                  ← 自己标成"数字用户线"
但 Scamalytics   = Server: Yes + "commercial server"    ← 风控库不认
```

**→ 三条结论**：

1. **"换个国家买"不等于"换掉同源"** —— 经纪人的号段**横跨多国**（借不同 Tier-1 的段广播）；
2. **`hostname` 和 `Connection type` 是自己填的，可以造假** —— **只有 RIR 注册记录和第三方风控字段不可伪造**；
3. **RDAP 写 GTT 时，真相藏在 Scamalytics 的 `ISP Name` 栏里**（见下一节）。

---

## 九、读 Scamalytics 的一个坑：**两个字段都要看**

本仓库早期写的是"**`Organization Name` 才是真相**"（德国案例：`ISP Name = NTT`、`Organization = Arisk`）。

**但补测时出现了完全相反的情况**：

| IP | `ISP Name` | `Organization Name` | 真正持有者 |
|---|---|---|---|
| `145.79.126.x`（德国） | NTT America | **Arisk** ← 这里 Org 栏才是真相 | Arisk |
| `64.50.130.19`（美国） | **Arisk Communications inc** ← 这里 ISP 栏才是真相 | GTT | Arisk |

**→ 修正后的读法**：

> **两个字段都读：哪个是"运营商 / 经纪人"，哪个就是真相；另一个是"广播方 / 管道"。**
> **不要把 `Organization Name` 当成唯一真相 —— 字段位置在不同记录里会换。**

---

## 十、收尾

> **不要问"哪家好"，要问"这个 IP 是谁的"。**
> **号段能被换标签，但换不掉注册记录。**
>
> **而且 —— 经纪人不止在一个国家有货。换国家，未必换得掉同源。**
