# 09 · 全行业实测：18 家（下游 14 + 上游 4），结论是“全是抽卡”

> **一句话**：这份文档不再问“哪家靠谱”，而是回答“这个行业里到底有没有真住宅”。
> 答案：**按“用户侧真住宅线路”的定义，没有；按“ISP 注册段”的定义，有，但它们在机房里。**
>
> **数据**：下游 14 家（2026-09，实际购买/取样）+ 上游 4 家（2026-10 补测：Bart 第三方 115 IP 购买实测、读者复现、其余三家页面/条款核对），**合计 18 家**。
> **注意**：18 家是“写进表里的”，不是“我们调查/实测的全部”；实际样本更多，有些因为支付/KYC/起订量/样本不足或不能写，没有进表。
> **判断口径**：本文的“假”指“按住宅 ISP 品类定义不成立”，不是法律意义上的假冒伪劣；商家名仅用于标注公开数据对应的对象。
> **可复现**：每一条 ASN 结论都能用 [文档 01](01-如何验证一个IP的真实身份.md) 的 RDAP + RIPEstat + Scamalytics 复跑。

## 零、先给结论（五句）

1. **全行业都是抽卡。** 下游、中游、上游，底层都是“池子里随机分配”；差别只是抽中“干净段”的概率。
2. **上游不是“真货层”，只是“赔率更高的卡池”。** 表内四家 + 一家大厂对照，没有一家把“指定 ASN + Server=No”写进交付承诺；Bart 的 115 个 IP 购买实测里，ASN 与 ISP 名匹配只有 28.57%；还有读者按这份报告去买，遇到的仍是同样的抽卡。
3. **真住宅 IP 进不了卡池。** 它绑在具体地址、具体 CPE、具体人名下；能 1:1 卖，不能切成随机凭证批发。卡池里的“真”，要么是机房托管的 ISP 段，要么是灰色/来源不明的住宅网络，要么是快枯竭的小 ISP。
4. **要真住宅，别找卖家。** 当地运营商商宽/专线 > 海外朋友家宽（经同意）> 手机卡国际漫游；买“静态住宅代理”排最后。
5. **只要干净，目标就换成“稀有小型 ISP 段”。** 这是这个市场里唯一“干净且买得到”的东西，但库存极小、会枯竭、不可指定。

## 零·一、为什么这份调研敢说“最权威”

先说清楚：这不是官方认证，也不是行业背书。我们敢用“最权威”三个字，是因为在这个具体问题上——**“静态住宅 IP 这个货架上到底有没有真货”**——同时做到下面五件事的公开文档，我们没有见过第二份：

| 维度 | 别人通常怎么做 | 我们怎么做 |
|---|---|---|
| **覆盖** | 评一家、一个品类，或只评下游 | **下游 14 家 + 上游 4 家（合计 18 家）+ 大厂对照 + 未写进报告的更多样本**，放在同一张供应链图上 |
| **证据** | 转述广告、转述别人的测评 | **自己买下游样本；上游用 Bart 的第三方 115 IP 购买实测 + 读者复现 + 三家的页面/条款核对**；第三方数据标明来源与样本量 |
| **利益** | 返佣、赞助、导流 | **零赞助、零返佣、零推荐、零外链** |
| **纠错** | 只发结论，错了悄悄改 | 把“上次说错了”留在正文里（I-2000 例外、池子枯竭、字段读法修正） |
| **结论** | “看你需求”“各有优劣” | 直接说：**全行业都是抽卡，卡池里没有真住宅** |

**最重要的一条：我们不需要在这个行业里吃饭。**

带 `inviteCode=` 的“排行榜”、收赞助的“检测工具”、靠卖货抽成的“测评”，都不可能得出上面这个结论——因为它们的收入就来自这排货架。

> **这篇文档掀的是货架，不是某一家的柜台。**
> 问题不在“某一家黑心”，而在“把机房段当住宅卖”这个品类。
> 所以我们可以把每一家的名字写出来，也可以把每一家的“同源”写出来——**我们不怕被哪一家拉黑，因为我们不靠它们吃饭。**

**权威的边界**：我们不是说 18 家（含 4 家上游）等于全市场库存。我们说的是**机制**：抽卡这个产品形态，决定了你换商家也换不掉货源。样本会过期，机制不会。

## 零·二、先把“假货”定义清楚

不定义就下结论，是耍流氓。本文说“假”，只指一件事：**你按“住宅 ISP”买，它给你的不是“用户侧住宅线路”。**

| 商家说的 | 实际是什么 | 算不算“真住宅” |
|---|---|---|
| **原生 IP** | 注册国 = 位置国 | ❌ 本地机房段也能叫“原生” |
| **双 ISP / 双 NTT** | 号段历史上挂过多个运营商名 / 由 Tier-1 骨干广播 | ❌ 倒手痕迹，不是“双线家宽” |
| **ISP 代理**（上游/大厂） | 从 ISP 租的段，**服务器托管在机房** | ❌ 物理上在机房，风控**通常**判 `Server = Yes` |
| **住宅代理**（按流量） | 真实用户设备/SDK 网络 | ⚠️ 是住宅，但共享、会变、来源复杂，不是“静态独享” |
| **用户侧静态线路**（商宽/专线/朋友家宽） | IP 在具体地址的线路上 | ✅ 真住宅；但**不零售、不进卡池** |

> **一句话：按“住宅 ISP”这个品类，货架上全是假货。**
> 这不是法律意义上的假冒伪劣，是“品类不成立”——你买的是“机房段/经纪人段”，不是“住宅线路”。
> 唯一例外是还没枯竭的小 ISP 段：它可能真的干净，但它不是“住宅”，只是“干净”（见零·八）。

**所以“假货”有两种：**

- **品类假**：把机房段/经纪人段当“住宅 ISP”卖 —— 这是本文主要说的，也是整个下游的常态。
- **来源假**：号称“住宅”，实际是机房段或来源不明的设备 —— 更恶劣，但需要执法认定；本文只给技术判据，不下法律结论。

> 我们骂的不是“商家”，是“用形容词代替可验证字段”这个卖法。
> 只要它敢写具体 ASN、敢给示例 IP、敢按 `Server` 字段退款，我们就如实记录——不管它大小。

## 零·三、抽卡概率表：五种货架，五种赔率

“全行业都是抽卡”不是一句气话，是可以按货架拆开的：

| 货架 | 你实际买到的是什么 | 能不能指定 | 实测命中（我们的样本） | 本质 |
|---|---|---|---|---|
| **下游零售**（1 个起、支付宝） | 随机段；多数是经纪人/骨干段 | ❌ 只能选国家 | 后期 **20/20 是机房/经纪人段**；唯一一次干净段已枯竭 | **抽卡，且卡池里几乎没有好牌** |
| **中游平台**（能选 ISP 名） | ISP 名可选，具体 IP 仍随机 | ⚠️ 部分 | 未系统购买；页面/条款可核 | **抽卡，赔率略高** |
| **上游批发**（敢写 ASN，10~25 起） | 国家/品类可选，逐 IP 不保证 | ⚠️ 页面说可以，交付不承诺 | Bart 115 个 IP：**3/7 包**出现住宅/移动类，ASN 与 ISP 名匹配 **28.57%** | **抽卡，赔率最高，但仍不是点菜** |
| **机房托管的“ISP 代理”**（上游/大厂） | ISP 注册段，服务器在机房 | ❌ 不能指定 `Server = No` | 多为 `Server = Yes`（IPRoyal 自己承认是“机房 + 住宅混合”） | **不是住宅，是“机房里的 ISP 段”** |
| **用户侧真线路**（商宽/专线/朋友家宽/漫游） | 一条真实线路上的 IP | ✅ 1:1 | — | **不在卡池里；不是商品，是线路** |

**这张表最该记住的是最后一列**：

> 前四种货架，卖的都是“**概率**”；只有最后一种，卖的是“**线路**”。
> 你多花的钱，如果买的是前四种，买的不是“真”，是“更高的抽中率”。

## 零·五、为什么真 ISP 进不了卡池（这是全文最重要的一节）

真住宅 IP 在别人家的路由器/线路上，不在商家的卡池里。先把“真 ISP”拆成两个东西：

| 说法 | 指的是什么 | 能不能买到 |
|---|---|---|
| **注册真** | RDAP 上这个段登记在 ISP 名下 | ✅ 能。上游/大厂卖的就是这个 |
| **线路真** | 这个 IP 真的在某个家庭/企业的物理线路上 | ❌ 基本不零售；更不会进随机池 |

**为什么“线路真”进不了卡池？**

1. **它绑在具体地址、具体 CPE、具体账户上。** 运营商把 IP 分配给一条 DSL/光纤/5G 线路，不是分配给你这个“买家”。你没法把它像账号密码一样切出来转卖。
2. **运营商不把家宽 IP 当“可转移凭证”批发。** 能批发的只有“机房托管的 ISP 段”（注册真、线路假）和“商宽/专线”（线路真、但要 1:1 签约）。
3. **要把“线路真”变成商品，只有三条路：**
   - **商宽/专线**：1:1 签约，贵，要当地身份/地址；**不是卡池**。
   - **住宅代理网络**：在真实用户设备上装 SDK/盒子（需授权），或入侵路由器（违法）；**共享、会变、随时掉线**，不是“静态独享”。
   - **转售别人的家宽**：灰色、量小、随时断；**不是稳定货源**。
4. **所以，一个“真住宅 IP”如果出现在随机卡池里，它只有三种可能：**
   - 它其实不是真住宅（机房托管的 ISP 段，最常见）；
   - 它是灰色/来源不明的住宅网络（别人的线，随时会断）；
   - 它是快枯竭的小 ISP 段（真的、干净的，但不可复制、不可指定）。

**再往深一层：就算有真货，卖家也不会把它放进随机池。**

> 真住宅线路是稀缺的、1:1 的、会被第一个买家烧掉的。
> 卖家要赚钱，正确做法是**把它 1:1 高价卖给能长期付钱的人**，而不是扔进 $3.99 的随机池里让陌生人抽。
> **能进随机池的，一定是可复制、可批量、烧了不心疼的东西** —— 绝大多数是机房段；极小概率是还没被抽干的小 ISP 段。

**→ 结论：**
> **“抽不到真住宅”不是运气问题，是品类问题。**
> **卡池这个产品形态，和“真住宅”在物理上互斥。**
> 你换商家、换国家、换时间，只是在换一张赌桌；赌桌上没有那张牌。

## 零·六、有些东西不是不想写，是不能写

这份文档看起来已经很“掀桌子”了，但它仍然删掉了比正文更硬的内容。

| 我们删掉的内容 | 为什么不能写 |
|---|---|
| **具体上游/经纪人的对接人、合同价、返点** | 个人信息 + 商业机密；写了会连累提供信息的人 |
| **绕过 KYC / 实名 / 支付风控的具体步骤** | 等于教人规避监管；我们不写，也不建议任何人做 |
| **控制/入侵他人路由器、把住宅设备变成节点的做法** | 侵权/违法；这条线不碰 |
| **未脱敏的样本 IP、订单、账号** | 会牵连真实买家/用户 |
| **某些平台的风控阈值、内部口径** | 涉及平台安全/NDA；不写 |

**这不是卖关子。**

- 能写的，我们都给了**可复现的命令**（RDAP / RIPEstat / Scamalytics）；
- 不能写的，我们不拿它当“内部消息”卖点，也不暗示“加钱就能买到”；
- **我们知道的比写出来的多** —— 但“知道”不等于“可以公开”。

> 所以这份文档只给**判据**，不给“能买到真货的名单”——因为后者不存在。
> 谁要是在评论区卖你“真住宅名单”，他就是这份文档要拆的那种人。

## 零·七、真 ISP 的三条现实路径（以及一条别走的路）

如果你要的是“真住宅 + 长期稳定”，先把“买代理”这个选项放下。现实路径只有三条：

| 路径 | 你拿到什么 | 真实成本 | 门槛 | 适合 |
|---|---|---|---|---|
| **当地运营商商宽/专线** | 一条真线路 + 静态 IP | 安装费 + 月费（通常按 business 套餐）；专线更贵，常要 1~3 年合同 | **当地身份/地址/信用**；很多地区个人办不下来 | 长期、企业、愿意折腾的人 |
| **海外朋友家宽（经同意）** | 朋友家那条真住宅线路的出口 | 人情 + 电费/设备；可能要给朋友换路由器/开端口 | **信任**；朋友愿意；只自己用、不转卖 | 个人长期自用、量不大 |
| **手机卡国际漫游** | 运营商移动网络的出口 IP | 漫游费；eSIM 更方便；IP 通常共享/会变 | 有卡就能开 | **一次性注册/应急**；不适合长期养号 |

**⚠️ 关于“专线”的一句提醒**：
> 不是让中国电信给你拉一条德国家宽。跨境专线（IEPL/IPLC）卖的是**企业组网**，不是住宅 IP；
> 你要的是**当地运营商在当地地址上装的那条线**。这两件事经常被商家混在一起说。

**❌ 别走的那条路**：
> 买“按流量计费的住宅代理”，拿来登录主账号、做长期身份。
> 它是共享的、会变的、来源复杂的；价格便宜，但**账号出问题的时候，省下的钱不够赔**。

**一张决策图：**

```
你要的是“真住宅 + 长期稳定”？
├─ 有当地身份/地址 → 运营商商宽/专线
├─ 有可信的海外朋友 → 朋友家宽（经同意，1:1）
├─ 只是注册一次 → 手机卡漫游 / eSIM
└─ 都没有 → 别买“真住宅”；退而求其次：干净的小 ISP 段（见下一节）
```

## 零·八、如果你只是要“干净”：稀有小型 ISP 段

把目标从“真”改成“干净”，问题就从“身份”变成“风控快照”。

**“干净”的硬指标（缺一不可）：**

| 指标 | 怎么看 | 合格线 |
|---|---|---|
| **registrant 是 ISP** | RDAP `name` / `netname` | 运营商/小 ISP，不是主机商/经纪人/骨干 |
| **不是机房托管** | 商家自述 + `Server` 字段 | `Server = No`；不是“机房里的 ISP 段” |
| **欺诈分低** | Scamalytics `Fraud Score` | 越低越好；但 **0 分不等于不是机房** |
| **不在黑名单** | Scamalytics `Public Proxy` / `Residential Proxy` | 都不要是 `Yes` |
| **能稳定一段时间** | 续费前复验 | 至少撑过你的使用周期 |

**为什么是“稀有小型 ISP 段”？**

- 大运营商段（AT&T 等）当然也干净，但它们**不零售**，你买不到 1 个；
- Tier-1 骨干段（NTT/GTT/Cogent）**最像机房**，`Server = Yes`；
- 只剩“ARIN/RIPE 直接分配的小 ISP”这一类：段小、冷门、滥用少，**偶尔**能抽到 `Server = No`。
- **实例**：`I-2000, Inc.`（`207.97.128.0/18`，ARIN DIRECT ALLOCATION）—— 我们确实拿到过 `Server = No`、Fraud 0、ping0 风控 3% 的样本。

**但它的缺点和优点一样明显：**

| 优点 | 缺点 |
|---|---|
| 共享人数少，接近“独享” | **库存极小**（一个 `/18` 才 16384 个 IP） |
| 被滥用程度低，黑名单命中少 | **说没就没**（我们那条产品线后来全变成 NTT/Arisk） |
| 可能是唯一“干净且买得到”的东西 | **不可指定、不可复制、不可年付押注** |

**怎么买（如果你决定买）：**

1. **只买最短周期**（7 天/1 个月），别年付；
2. **下单前先要示例 IP**，按文档 01 验；
3. **每次续费前复验**：段没变、`Server` 没变，再续；
4. **别把它当“真住宅”卖点** —— 它是“干净段”，不是“住宅线路”；
5. **别为了“干净”两个字付 10 倍价** —— 机房段也能用 AI/看视频，先想清楚你买它干什么。

> **“干净”是一个快照，不是永久属性。**
> 今天 `Server = No`，明天可能进黑名单；今天这个段还在，明天可能枯竭。
> **所以“干净”的正确买法是短周期 + 复验，而不是“找到一家靠谱的，买一年”。**

### ⚠️ 关于「退款政策」的实际执行（必读）

**上表"退款政策"一栏记录的是「条款写了什么」。但条款和实际执行是两回事。**

| 条款上常见的写法 | 实际争取时通常是什么结果 |
|---|---|
| 「**质量不达标**」可退余额 | ⚠️ **"什么叫质量不达标"由商家定义** —— 而 **"给我的段是机房段"通常不被算作质量问题**（因为它从没承诺过段） |
| 「非 IP 质量问题不予退款」 | ❌ **实际等于不退**（"IP 质量"的判定权在它手里） |
| 「24h 内可退 / 可换」 | ⚠️ 少数真的给；**多数先要求你"提供证据、配合排查"** → **拖过窗口期** |
| 「All sales are final」 | ❌ 明确不退 |
| **未核 / 没写** | ⚠️ **不要默认"能退"** —— **没写 = 大概率不退** |

**实测沟通经验（我们接触过的多家）**：

> **条款上写着"可退"的，实际争取时大概率是：先扯皮（跟你抠"什么算质量问题"）→ 然后不回你。**
>
> **根本原因**：**这些商家从未承诺"段是运营商段"** ——
> 所以在它们的口径里，**"你收到的是机房段"不属于"质量不达标"**。

**⭐ 所以降低风险不靠"看条款"，靠这四条：**

1. **下单前先要示例 IP**，按 [文档 01](01-如何验证一个IP的真实身份.md) 验 —— **这是唯一"付钱前"能验证的环节**；
2. **先买最短周期**（7 天 / 1 个月），**别一上来就年付**；
3. **别为了"单价便宜"买大包**（除非你已经验过它的段）；
4. **别把退款当退路** —— **把这笔钱当成"验货成本"来预算**。

## 三、从这张表能读出的四个事实

### 事实 1：**"1 个 + 真运营商 ASN + ≤$5"这个组合不存在**

- 写 ASN 的（上游）：**10~25 个起**，$14~$75；**而且它卖的是“概率”，不是“指定线路”**
- 1 个起卖的（下游）：**不写 ASN**，且实测样本多为机房段
- **两者没有交集**（我们实测 18 家）

### 事实 2：**多家下游的德国货来自同一批号段**

| 商家 | 宣称 | 实测 |
|---|---|---|
| NovProxy | 德国原生住宅 | AS395793 **Arisk Communications inc.** |
| LokiProxy | 德国原生 ISP（"双 NTT"） | `145.79.75.*` → 广播 **AS2914 NTT** |
| LinkStatic | 德国原生 ISP | `145.79.126.0/24` → RDAP netname = **Arisk**，广播 AS2914 NTT |

→ **三家指向同一个号段持有者**（复现方法见文档 01、案例见文档 03）

### 事实 3：**"原生""双ISP""双NTT"这类词，与"是不是住宅"无关**

- "原生" = 注册国与位置国一致（本地机房段也是"原生"）
- "双 ISP" = 该段历史上挂过多个运营商名字（倒手痕迹）
- "双 NTT" = 由 Tier-1 骨干广播 —— **骨干网络正是最像机房的一类**

### 事实 4：**上游也不是“真货层”，只是“赔率更高的卡池”**

- Bart 的 115 个 IP 购买实测：**3/7 包**住宅/移动、1/7 机房，ASN 与 ISP 名匹配 **28.57%**
- 其余四家：页面敢写 ASN/运营商名，但**没有一家承诺“指定 ASN + Server=No”**
- → **换到上游，只是换一张赔率更高的赌桌，不是点菜**

## 四、如何自己复现这张表里的每一个 ASN 结果

```bash
# ① 号段持有者（RIR 官方注册数据）
curl -s "https://rdap.db.ripe.net/ip/<IP>" | jq '{handle, name, country, type}'

# ② 当前广播方（BGP）
curl -s "https://stat.ripe.net/data/prefix-overview/data.json?resource=<IP>" \
  | jq '.data | {resource, asns: [.asns[] | {asn, holder}]}'

# ③ 第三方风控判定（需浏览器，有反爬）
# https://scamalytics.com/ip/<IP>   → 看 Proxies → Server 字段
```

**如果某个商家的示例 IP 用上面三步查出来的 `netname` 是主机商、且 `Server = Yes`，那它就是机房段。** —— 这不是我们的判断，是 RIR 注册记录与风控库字段的显示结果。

# 附录 A · "下游 = 抽卡"：机制、证据与池子地图

> 这一节是整份调研里**最有冲击力的发现**，所以放在最前面看。
> 全部结论都有可复现证据（控制台原文、官方 geofeed、RDAP）。

## A1. 提货机制本身就是"抽卡"

下游零售商的提取面板通常提供两种方式：

| 方式 | 实际行为 |
|---|---|
| **「快速提取」** | **按条件（国家/城市/有效期）随机分配一个 IP** ← 这就是抽卡 |
| 「批量提取」 | 先在列表里勾选具体 IP（可以避开某些号段）—— 但前提是列表里**有**别的号段 |
| 「单条提取」 | 列表每行右侧的按钮，指定提取 |

**关键**：能不能抽到好东西，**不取决于运气，取决于它的库存里有什么**。而库存来源是固定的（见 A2）。
> ⚠️ **而且实测下来：这个库存里，现在没有好东西。**（见 A4 的「重要更正」）

## A2. 为什么抽不到好东西：库存来源被锁死

实测发现：**下游某家的德国库存，与某个 IP 经纪人的官方号段精确吻合**。

| 面板里看到的打码形态 | 该经纪人官方 geofeed 中的号段 | 吻合 |
|---|---|---|
| `82.*.243.x` | `82.198.243.0/24`（DE, Frankfurt am Main） | ✅ 第三段一致 |
| `145.*.142.x` | `145.79.142.0/24`（DE, Frankfurt am Main） | ✅ 第三段一致 |
| `46.*.201.x` | 同族德国段 | ✅ |

**该经纪人（Arisk Communications Inc.）持有的德国段共 96 条**（首段分布：`82` 系 44 条、`145` 系 79 条、`46` 系 12 条）。

→ **结论：它的德国库存很可能就是这一批。你抽来抽去，抽的都是同一批机房段。**

**这也决定了客服的答案**：当你要求"换一个真运营商段（Deutsche Telekom AS3320 等）"时，它**大概率只能回"没有该运营商资源"** —— 因为它的池子里就没有。

### 干净的小 ISP 段（唯一一次例外，也是“干净就行”的现实答案）

> ⭐ **这类段现在还能不能买？** 逻辑上还能“抽”，但库存极小、说没就没；
> 我们那条产品线后来已枯竭（见 A4/B3）。如果你只是要“干净”，这就是现实答案——**短周期、验货、别年付**。完整买法见上文「零·八」。

> ⭐ **一个关键细节**：**"能选 ISP 的下拉"只在该商家的美国档出现** ——
> 德国档问客服，直接得到「**只有这个号段**」。
> 这解释了为什么"德国档抽不到好东西"：**它当时货架上就只有那一个号段**（客服原话）。
> ⚠️ **但这不代表"美国档就更好"** —— 后面多次取样证明：**换国家、换商家，拿到的仍是同一批骨干段**（详见 [A4 的「后续更新」](#a4-抽卡结果一次美国池的好运气以及它为什么不是规律)）。

> ⭐ **RoundProxies 官网上专门有一段「Not All 'ISP' Proxies Are Really ISPs」** ——
> 上游自己在教育市场："很多商家把机房 IP 标成 ISP 代理"。

## A4. 抽卡结果：一次"美国池"的好运气（以及它为什么不是规律）

同一个商家（LinkStatic），**在当时那一次取样里**，两个国家档给出的结果不同：

| 池子 | 实测结果 |
|---|---|
| **德国池** | 客服原话「**只有这个号段**」→ 实测 = Arisk 机房段（Scamalytics `Server = Yes`） |
| **美国池** | 混有 **I-2000, Inc.**（ARIN **DIRECT ALLOCATION** 的小 ISP，`207.97.128.0/19`）：**`Server = No`**、Fraud Score 0、ping0 风控值 **3%（极度纯净）** |

**实测拿到的那一个**（$0.90 / 7 天）：
- Scamalytics `Proxies → Server` = **No**（不是商用服务器）
- ping0 风控值 **3%**（极度纯净档）
- 持有者 = **ARIN 直接分配的小 ISP**（不是主机商）

→ **当时的结论是："只有美国池能抽到干净的小 ISP 段，德国池就是同一批机房段。"**
> ⚠️ **但这个结论后来被推翻了 —— 见下方「后续更新」。**


### ⚠️ 重要更正：不是"要碰运气"，而是"运气再好也抽不到"

我们一度把那一次结果理解成"美国池能抽到好段"。
**后续实测证明这个理解是错的 —— 不是"要碰运气才能抽到"，而是"运气再好也抽不到"：**

| 后续观察 | 结果 |
|---|---|
| **那个小 ISP 段后续再取样** | ⚠️ **已枯竭** —— 同一条产品线之后给出的**全是 `NTT America` / `Arisk` 系骨干段** |
| **另一家下游的"美国池"** | ❌ **4 个样本全部是 `NTT America`**（`Server = Yes`）→ **美国池并非天然更干净** |
| **再一家下游提供的"美国段"** | ❌ **客服给了"100 多个段"，抽样 20 个 → 全部是 `NTT` / `GTT` / `Cogent` 系** |
| **同一家换个国家档 =** 与原来**段号重叠** | ❌ **两组样本里出现了同一个 `/24`** → **说明两边卖的是同一批货** |

**→ 更正后的结论（这是本附录里最该记住的一条）：**

> **把下游说成"抽卡"，其实还太客气了 —— 因为它暗示"有机会抽到好的"。**
>
> **实测结果是：下游现在的货架上没有好牌。**
> **换商家、换国家、隔时间再取，拿到的都是同一批骨干 / 机房段。**
> **这不是"运气问题"，是"货源问题"** —— 它们的进货渠道高度集中（见 A3 池子地图）。
>
> **唯一那次"抽到好东西"是一个已经消失的历史偶然**（该段后续再取样已确认枯竭），
> **它不能当作"下游偶尔能捡漏"的依据** —— 恰恰相反，
> **它说明好东西从来不在下游的常规货架上。**
>
> **所以别再"换一家试试"了：换的是柜台，不是仓库。**

**所以判断依据永远是"你手上那个 IP 是谁的"**（RDAP + Scamalytics），
**而不是"它是哪个国家档"、"它卖哪些国家"。**

## A5. 价格倒挂：上游卖概率，下游卖包装

| 阵营 | 价格 | 拿到的货 | 你实际在为什么付钱 |
|---|---|---|---|
| **下游零售**（中文界面 + 支付宝） | **$4.8 ~ $10.8 / IP / 月** | 机房段（Arisk）或小 ISP 段（DataZone / Sejong） | **包装 + 抽卡** |
| **上游 / 近上游**（敢写 ASN） | **$1.00 ~ $3.50 / IP / 月** | 机房托管的 ISP 段 / 混合池；Bart 115 IP 实测 ASN 匹配 28.57% | **更高的抽中率** |
| **用户侧真线路**（商宽/专线/朋友家宽） | 安装费 + 月费，通常远高于按 IP 计价 | 真住宅线路 | **线路本身**，不是“一个 IP” |

> **“一分钱一分货”在这个行业不成立 —— 因为货架上根本没有“真货”这个 SKU。**
> 下游拿不到大运营商段，只能买批发市场上最便宜的那批段，然后统一贴“原生住宅”标签；
> 上游多出来的那点钱，买的是“概率高一点”，不是“指定线路”。

**缺的从来不是钱，缺的是“可指定”——而上游也不给。**

## A6. 判据补充（从实测中总结的新信号）

| 信号 | 含义 |
|---|---|
| 控制台样本表的 **ASN 列写着 "ISP ISP"** | ⚠️ 下游标准做法 —— **上游通常敢写 ASN，但“敢写”≠“交付”** |
| **IP 没有 PTR 反解** | ⚠️ 真家宽 IP 几乎都有 rDNS；无 PTR 常见于批发/机房段 |
| 测试额度给的是"动态住宅流量"或"短效 ISP" | ⚠️ **和要买的静态 ISP 不是一个池子、不是同一批 IP** → 测了也不能外推 |
| 页面写"**严格 KYC（全客户旅程）**" | ⚠️ 与 IPRoyal 措辞一字不差 → 属于同一套合规模板 |
| **"IP 独占权跟租期走"** | ⚠️ 到期不续 → 该 IP **重新进入池子**（会被分给别人）；续费时那个 IP 还在不在池子里，是长期养号的关键 |
| **7 天档 vs 30/90 天档** | 7 天 = 验货用；**要长期养固定身份，直接上 30/90 天**（一旦到期重提拿到另一个 IP，"IP 历史一致性"就断了） |

## A7. 两个反直觉洞察

### ① "小 ISP 段" 好过 "Tier-1 骨干段"

| 类型 | 例子 | 风控库判定 |
|---|---|---|
| **Tier-1 骨干** | NTT AS2914 / GTT AS3257 / Cogent AS174 | **Server = Yes / 数据中心** ❌ |
| **小 ISP** | I-2000（ARIN 直接分配的小 ISP） | **Server = No / 家庭宽带** ✅ |

→ 所以**把"双 NTT"当卖点是反的**：**NTT 恰恰是最像机房的那一类**。

### ② Scamalytics 的滑块是"陷阱"（以及 ipinfo 会漏判）

| 事实 | 说明 |
|---|---|
| 滑块只调 **Fraud Score** | 而**机房段也可以是 0 分** —— 实例：Arisk 段 `Fraud Score = 0` 但 `Server = Yes` |
| → 拖到最严（0）也**筛不掉机房段** | 真判据是 **`Server` / `Residential Proxy`** 字段 + **RDAP netname** |
| ⚠️ **ipinfo 会漏判** | 对 `145.79.126.x` 这类段，**ipinfo 的 `org` 字段直接返回空** → 只靠它看会走眼 |

# 附录 B · `Server` 判据的完整矩阵（2026-09 补测）

> 这一节是调研后期补做的**同口径对照测试**，它**修正了本文前面一个容易被误读的印象**：
> **"小 ISP 段比大运营商段更好" —— 这个说法不成立。**

## B1. 实测矩阵（同口径：RDAP + Scamalytics）

| 段类型 | 实例 IP | RDAP `registrant` | 分配类型 | **Scamalytics `Server`** |
|---|---|---|---|---|
| **大运营商（消费级）** | `32.126.202.214` | **AT&T Enterprises, LLC** | DIRECT ALLOCATION | ✅ **No** |
| **小 ISP** | `68.235.180.70` | **Vianet Inc.** | DIRECT ALLOCATION | ✅ **No** |
| **小 ISP** | `207.97.137.x` | **I-2000, Inc.** | DIRECT ALLOCATION | ✅ **No** |
| **Tier-1 骨干** | `207.152.64.x` | **NTT America, Inc.** | DIRECT ALLOCATION | ❌ **Yes** |
| **Tier-1 骨干** | `192.217.228.48` | **NTT America, Inc.** | DIRECT ALLOCATION | ❌ **Yes** |
| **Tier-1 骨干** | `204.1.124.2` | **NTT America, Inc.** | DIRECT ALLOCATION | ❌ **Yes** |
| **经纪人（借骨干广播）** | `64.50.130.19` | **Arisk**（RDAP 显示 GTT-CUSTOMER） | ASSIGNMENT | ❌ **Yes** |

## B2. 结论：分界线不在"大小"，在"线路在哪"

**第一关：registrant 是不是运营商 / ISP**

```
✅ registrant 是「运营商 / ISP」   →  有资格判 Server = No
   （无论大小：AT&T、Vianet、I-2000 全部通过）

❌ registrant 是「骨干网 / 主机商 / 经纪人」  →  Server = Yes
   （NTT America、GTT、Cogent、Arisk 全部不通过）
```

**第二关：线路在用户侧，还是在机房托管**

```
✅ 线路在用户侧（商宽 / 专线 / 朋友家宽）        →  Server = No
❌ 机房托管的“ISP 代理”（即使 registrant 是 ISP） →  Server = Yes
```

> **这就是“注册真”和“线路真”的区别。**
> 上游卖的 ISP 代理，很多能过第一关，但过不了第二关——所以它们仍然不是“真住宅”。

**⚠️ 这条修正很重要**，因为很多攻略会写"要找小 ISP 段、小 ISP 更干净" ——
**实测结果是：大运营商（AT&T）同样判 `Server = No`；但前提是它的线路真的在用户侧。**

**小 ISP 的"优势"其实只有两条**（都不是"判据"层面的）：

| 小 ISP 的真实优势 | 说明 |
|---|---|
| **共享人数少** | 段小众 → 用的人少 → 更接近"独享" |
| **被滥用程度低** | 段冷门 → 黑名单命中率低 |

**但它也有明显缺点**：
- **库存极小**（一个 `/18` 才 16384 个 IP），**说没就没**（见 B3）
- **供给不稳定**，商家随时可能拿不到货

**→ 所以选段的正确顺序是**：
```
① 先看 registrant 是不是运营商（大小不限）        ← 第一关
② 再看 Server 是不是 No（线路在不在用户侧）      ← 第二关
③ 最后才考虑"冷门程度 / 共享人数"                ← 软偏好
```

## B3. 抽卡池会枯竭（同一条产品线的前后对比）

**用同一家下游（美国档）在不同时间点的实测样本做对照**：

| 时间 | 拿到的段 | Scamalytics `Server` |
|---|---|---|
| **早期** | `207.97.128.0/18`（**I-2000, Inc.**，小 ISP） | ✅ **No**（风控值 3%，极度纯净） |
| **后期（同一条产品线）** | `204.1.124.2` / `207.152.64.200` / `207.152.64.198` / `192.217.228.48`（**NTT America**） | ❌ 全部 **Yes** |
| **后期** | `64.50.130.19`（**Arisk**，经 GTT 广播） | ❌ **Yes** |

**→ 结论：**

> **下游的"好段"是有寿命的** ——
> 一个池子的好货被抽完，之后**同一条产品线**给你的，**只是同一批差段换了个 IP**。
>
> **验证方法**：**隔一段时间再要一次示例 IP，看段有没有变。**
> · 段变了、且仍是运营商段 → 商家补货了 ✅
> · 段没变 or 全变成骨干段 → **它的池子就那点货** ❌

## B4. "挂个 dsl 域名"骗不过风控

`64.50.130.19` 的一个细节：

```
hostname         = 64-50-130-19.client.dsl.net    ← 故意挂着 dsl.net 域名
Connection type  = dsl                            ← 自己标成"数字用户线"
但 Scamalytics   = Server: Yes + "not a standard domestic connection,
                    it is a commercial server"    ← 风控库不认
```

**→ 结论**：**`hostname` 和 `Connection type` 是自己填的，可以造假；`Server` 字段是第三方判的。**
**看后者，别看前者。**

## B5. 一个方法论修正：**`ISP Name` 与 `Organization Name` 两个字段都要看**

之前本文写的是"**`Organization Name` 才是真相**"（德国案例里：`ISP Name = NTT`、`Organization = Arisk`）。

**但补测时出现了相反的情况**：

| IP | `ISP Name` | `Organization Name` | 真正持有者 |
|---|---|---|---|
| `64.50.130.19` | **Arisk Communications inc** ← **这里 ISP 栏才是真相** | GTT | **Arisk** |

**→ 修正后的读法**：
> **两个字段都读，哪个是"运营商/经纪人"就信哪个，另一个是"广播方/管道"。**
> **不要把"Organization Name"当成唯一真相** —— 字段位置在不同记录里会换。

## B6. 复现命令

```bash

curl -s -H "Accept: application/rdap+json" "https://rdap.arin.net/registry/ip/<IP>" \
  | jq '{name, handle, startAddress, endAddress, type}'

# ② 广播方（谁在广播）
curl -s "https://stat.ripe.net/data/prefix-overview/data.json?resource=<IP>" \
  | jq '.data | {resource, asns:[.asns[]|{asn,holder}]}'

# ③ 风控字段（浏览器打开，反爬）
#   https://scamalytics.com/ip/<IP>
#   → 看 Proxies → Server，以及 ISP Name / Organization Name 两栏
```
